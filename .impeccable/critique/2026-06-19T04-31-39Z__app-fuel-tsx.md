## Anti-Patterns Verdict

**Not AI slop.** Screen has coherent information hierarchy (four RowGroups: car profile → reminders → current state → stations), token discipline throughout, and comments explaining decisions. BucketPill component thoughtful with four-affordance selected state. No gratuitous decoration, gradient fills, eyebrow labels on every group. Brand register holds.

**One potential drift:** `fillBtn` style sets `borderColor: colors.freshgreen` on the unselected state. Green-bordered unselected buttons read as a CTA cluster, subtly against the "brand greens carry the interactive surface" principle. Compare with BucketPill and segmentItem patterns using `colors.separatorSubtle` on unselected border. Minor internal inconsistency, not a reserved-color violation.

## Cognitive Load

**Moderate on first visit, low on return.** Screen has 4–6 decisions: car name (optional), fuel type (4 options), reminders on/off, cadence days, distance on/off, tank range (4 presets + custom). Substantial form for a settings screen.

Cognitive cost front-loaded: two most demanding choices (fuel type, cadence) come before any reward signal. By time user reaches current-state section (only "live" part), most work already done.

**Progressive disclosure present but incomplete.** Reminders on/off gating cadence stepper and distance toggle is well done. Distance on/off gating bucket grid correct. But entire conditional block collapses neatly when reminders off, and screen is also the only place to manage Preferred Stations — a task with nothing to do with refuel reminders but lives on same page with no visual demarcation.

**Custom range flow adds a mini-form within the form.** Opening Custom BucketPill appends TextInput + "mi" label below pill grid. Layout shift is abrupt without animation. At AX5, input row and pill row could compete for vertical space.

## Emotional Journey

**Entering the screen** — Arriving from /search Fuel card, user faces clean grouped form. SettingsHeader centers title with back and close. Emotional register neutral-functional: this is admin, not safety moment. Appropriate for "Steady Companion."

**First-time setup (reminders off, distanceEnabled off)** — Two RowGroups visible. "Remind me to refuel" toggle is main CTA but reads as row label and switch with no surrounding copy making the case for why. Coaching voice absent. First-time user without intent to enable reminders may leave without engaging.

**After enabling reminders** — Cadence stepper and distance toggle appear. Stepper has satisfying ± mechanic, but 1-day increments up to 60 days means user wanting 30-day cadence taps Plus 23 times. Emotional low point for Casey persona.

**After saving with reminders on** — On return, "Next reminder" date and fill-fraction buttons appear. Warmest part of screen — "I filled up" section feels like it might be used regularly. Freshgreen border, Check icon on selected, haptic on submit: all right. Current-cycle gating means unsaved changes don't prematurely show fill row.

**Preferred Stations section** — Emotional register drops. Section sits below all reminder machinery; users who arrived to manage stations must scroll past controls they may not care about. For Black driver curating list of trusted stations (safety-meaningful act), buried list at bottom of reminders form is mild discoverability failure.

## What's Working

**1. BucketPill selected state is thorough.** Four-affordance selected (background, icon fill, label color, Check prefix) clear and redundant in right way — colorblind user gets Check and color change. a11y role correct.

**2. Fuel-type change reset is principled.** Clearing bucket on fuel-type change and showing contextual note is exactly right. Auto-mapping 350mi gas Sedan to 350mi EV bucket would silently misconfigure. Comment explains: "Auto-mapping would silently change a number the user didn't approve."

**3. Token discipline is complete.** No inlined hex colors, font sizes, or spacing values. Every design value pulls from `theme/`.

## Priority Issues

**[P0] Save with distance enabled but no range selected produces silent misconfiguration**
- What: When `distanceEnabled=true` but no bucket/custom range, `rangeMiles` is null. `handleSave` passes `distanceEnabled ? rangeMiles : null`, so `rangeMiles=null` and `rangeSource='none'` get stored — but toggle appears ON. Next time user opens, toggle is rehydrated from `profile.rangeSource !== 'none'` (false), so toggle resets to OFF. Silent reset loop.
- Why it matters: A Black driver using distance triggers as safety net (driven miles as proxy for unfamiliar territory) is silently not getting that feature. Failure invisible until they notice no reminders.
- Fix: Disable Save button (or surface inline validation) when `distanceEnabled && rangeMiles === null`. Message: "Pick a range to use distance reminders."

**[P1] Stepper has no acceleration — 30+ day cadences require many taps**
- What: Stepper increments by 1 day per press. MIN=1, MAX=60. User wanting 30 days starts from default 7 and taps Plus 23 times. No long-press repeat, no direct text entry, no preset options.
- Why it matters: Friction in a settings form is completion-rate killer. Casey abandons non-obvious forms. 23-tap interaction is non-obvious.
- Fix: Add long-press acceleration on stepper (start firing every 200ms after 400ms hold, increment by 5 after 10 rapid fires). OR replace stepper with preset pills (7d / 14d / 30d / custom) mirroring BucketPill pattern.

**[P1] Custom range input gives no indication of valid range bounds before entry**
- What: `MIN_RANGE = 20`, `MAX_RANGE = 800`. Placeholder is "e.g. 320". No validation feedback, no inline "(20–800 mi)" hint. User who types "1000" sees it silently clamp to 800 on blur.
- Why it matters: Silent clamping is error-prevention failure AND error-recovery failure. User's mental model diverges from saved value.
- Fix: Add range hint below custom input ("mi (20–800)"), and on commit if clamping occurred, momentarily surface clamped value: "Range set to 800 mi (maximum)."

**[P2] "Tank range" is engineering language; section needs plain-language reframe**
- What: `fieldLabel` reads "Tank range." Users think "how far do I go before refueling?", not "what is my tank range?"
- Why it matters: For Sam (deliberate language processing) and first-time users, opaque labels create friction.
- Fix: Rename to "How far before you refuel?" or "Range before empty". Or keep "Tank range" with subtext footnote.

**[P2] Fill-fraction row uses freshgreen borders on unselected state**
- What: `fillBtn`: `borderColor: colors.freshgreen` (unselected). Every other pill-like control on screen uses `borderColor: colors.separatorSubtle` on unselected.
- Why it matters: Freshgreen border reads as CTA, not radio option. Blurs reserved-color principle: freshgreen should carry active/selected state, not ambient unselected state.
- Fix: Change unselected `fillBtn` borderColor to `colors.separatorSubtle` or `colors.cardBorderSubtle`. Keep freshgreen fill on selected.

**[P2] Preferred Stations buried below reminder form with no navigational anchor**
- What: Preferred Stations RowGroup at bottom of scroll after all reminder controls. User entering specifically to manage trusted stations must scroll past all reminder machinery.
- Why it matters: For Black driver who has curated trusted stops (safety-meaningful act), trusted-station management is as important as reminder configuration. Burying frames it as afterthought.
- Fix: (a) Pull Preferred Stations into own screen (reachable from this screen's header or /search Fuel card), or (b) add visual weight to separate concerns — full-width divider or section spacer larger than inter-group gap.

**[P3] RowGroup separator inset assumes icon-bearing rows; fuel.tsx has none**
- What: RowGroup hairlines inset `marginLeft: spacing.md + 24 + spacing.md` (52pt) to run under icon column. fuel.tsx RowGroups are icon-less. Every hairline runs under 52pt of empty space.
- Why it matters: Minor visual misalignment — separator appears to inset past content.
- Fix: RowGroup should accept optional `separatorInset` prop (default: icon-column value; override: `spacing.md` for icon-less groups).

## Persona Red Flags

**Sam (accessibility, Dynamic Type, deliberate language processing):**
Stepper's `stepValue` ("7 days") has `minWidth: 72` at system type but not constrained at AX5 — text grows freely and row reflows. stepBtn `minHeight/minWidth: 44` correct, but stepper row uses `gap: spacing.lg` (24pt) — at AX5, Minus and Plus could be visually far from value label, separating control from reading. `fieldLabel` uses `subheadlineEmphasized` (15pt) fine at default but may feel small at Large Text.

`customRangeUnit` ("mi") rendered at `bodyRegular` but not paired with input's accessible label — VoiceOver user tabbing to unit label gets "mi" with no context that it describes the range input.

**Casey (distracted mobile user, one-handed thumb reach):**
Save button at bottom of scroll. On long form, Casey may not realize she hasn't saved. SettingsHeader Close (→ /home) and Back (→ previous) — neither labeled "discard changes," so casual tap silently discards form. No confirmation dialog for unsaved changes.

1-day-increment stepper is Casey's biggest frustration. Bi-weekly reminder (14 days) from default 7 = 7 Plus taps. Overshoot to 17 = 3 Minus taps. Requires sustained attention Casey doesn't have in a parking lot.

**Black driver assessing safety in a charged moment:**
This screen unlikely to be visited in a charged moment — setup/maintenance, not real-time safety. However, Preferred Stations intersects with safety preparation. Driver returning to check or update trusted-stops list (pre-drive safety ritual) finds it buried below form they may not need to touch. Emotional cost low absolute but signals misplaced priority.

No reserved-color violations. No orange, red, yellow, navy appear. Correct — not a safety-signaling surface.

## Minor Observations

1. `accessibilityRole="button"` on fuel-type segment items — effectively radio buttons (one of 4). `accessibilityState={{ selected }}` present but role is `button`. BucketPill correctly uses `radio`. Segment should follow suit, or RowGroup should carry `radiogroup`.
2. `StatusBar style="dark"` hardcoded — appropriate for light-bg screen.
3. `Trash` icon weight is `"regular"` on station remove — every other interactive icon uses `"fill"` on selected. `"bold"` or `"duotone"` would give more presence.
4. `nextLabel` uses `toLocaleDateString` (locale-aware, correct) but no `accessibilityLabel` override on `statusText` — VoiceOver hears "Next reminder: Mon Jun 23" as prose, fine but could be more deliberate.
5. Footer on fill-fraction RowGroup uses "us" — voice typically second-person elsewhere ("Star a gas station you trust"). "Tap how much you filled" is cleaner.
6. `handleCommitCustom` does not close `customRangeOpen` on valid input — after typing valid number and tapping Done, TextInput stays visible after value committed. Functional bug.

## Questions to Consider

1. Should "I filled up" live somewhere more discoverable? Home screen and/or refuel notification deep link more natural for repeat action than settings form.
2. Is Preferred Stations section in scope for this screen? Future `/stations` screen reachable from search, fuel card, and here would let both features stand on their own.
3. What is actual failure mode for a blank cadence? `saveProfile` sets `lastFilledAt = nowIso` on every enabled save — every Save resets reminder clock, even if user only updated car name.
4. Is fuel-change note dismissible? Currently auto-clears on next bucket pick. If user changes fuel type then taps Save without picking new bucket, note persists. `accessibilityLiveRegion="polite"`. Intentional?
5. How does EV experience differ? Bucket labels for electric are range-based (correct). But fill-fraction labels are pure fuel-tank language. EV driver "charged to 80%" rather than "filled up ¾". Is fill-fraction section used for EV at all, or conceptually gas/hybrid-only? Code doesn't distinguish.
