## Priority Issues

### P1

1. **home.tsx is a 4163-line god component.** 20+ useState, 10+ useRef, route calc + zone rendering + placement mode + browse sheet all in one file. Design maintenance risk.
2. **Pulled-over transition phase is uncontrollable.** 3s auto-advance with no user control. Fails WCAG 2.2.1. A person under stress reads slower; the system decides when they're ready.

### P2

3. **Review phase on /pulled-over has no visible progress indicator.** 5-view chevron nav with no "2 of 5" label. The route-cycle pattern already solves this on /home.
4. **Route-preview chip row can overwhelm on dense routes.** 7+ chips wrapping to multiple lines on narrow devices. Consider a net-score summary chip when count > 4.

### P3

5. **No help or explanation for the scoring system.** "Why this route?" is unanswered in the UI.
6. **pressedDim opacity (0.7) is slightly aggressive.** iOS native uses ~0.85.
7. **mapCoachButton white-on-freshgreen at 13pt** is below 4.5:1 WCAG AA.
8. **routeConditionsCaption at labelTertiary** is ~3.8:1 contrast, below AA.
9. **DragHandle used decoratively** in some places where swipe-to-dismiss is not wired.

## Persona Red Flags

- **Casey (distracted driver):** Report-placement flow has no driving-detection gate. User can place pins while moving.
- **Sam (VoiceOver):** Review phase position not announced. Daylight legend strip lacks non-color cue (the polyline has one, the legend doesn't).

## Strengths

1. Reserved-color discipline is genuinely exceptional — color carries meaning, never decoration.
2. Held-Question Rule is emotionally precise — regular weight reads as companion, not command.
3. Token-driven design is fully realized — zero inline magic numbers.
