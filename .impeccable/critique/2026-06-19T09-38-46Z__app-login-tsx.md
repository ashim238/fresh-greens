## Anti-Patterns Verdict

**Not AI slop.** Clear pass on PRODUCT.md anti-reference checklist: no gradient text, glassmorphism, eyebrow labels — two-action screen with no decorative chrome. Not generic ride-share SaaS — earthy palette, outlined (not filled) primary CTA. Not alarmist — `colors.red` only in error path (documented exception #8). Not sterile/clinical — "Welcome back" reads warm; car illustration carries community visual.

One borderline flag: error text uses `colors.red` + `typography.footnoteRegular` (13pt). At 13pt on `colors.burntgreen` background with white surrounding text, the red reads visually "hot" against earthy palette — not wrong, but worth monitoring as more error states added.

## Emotional Journey

**Arriving:** Returning user reaches `/login` via "Have an account? Log in" link on get-started. Known-state mode — used this before, expect fast return. "Welcome back" greeting lands correctly — warm without being effusive.

**Pressing the CTA:** Button dims (pressedDim 0.7) on press — correct HIG feedback. Apple sheet rises immediately. Haptic on success (`Haptics.NotificationFeedbackType.Success`) well-placed and matches "it worked" beat.

**Error state:** Emotional register breaks. "Sign-in failed. Please try again." reads cold and diagnostic — voice shifts from warm companion to error terminal. In charged moment (returning user trying to access app before drive, possibly in parking lot), opaque error with no recovery path is trust breach.

**Escape link:** "Don't have an account? Sign up" escape correctly placed below divider. But for returning user hitting auth failure, this link is wrong escape — they *do* have an account. No "try again later" or "something went wrong on our end" framing.

## What's Working

**1. Brand coherence is strong.** Wiltedgreen sky / burntgreen ground split, car illustration, earthy palette consistent with every other auth-adjacent screen.

**2. Accessibility implementation above average.** `accessibilityRole="button"`, `accessibilityState={{ busy, disabled }}`, `accessibilityLabel` on both Pressables and illustration — more careful than most RN auth screens.

**3. Route logic correctly hidden.** Login always routes to `/home`, skipping onboarding. Comment in code explains why. Users get where they're going.

## Priority Issues

**[P0] Error state lacks diagnostic differentiation**
- What: "Sign-in failed. Please try again." is sole error message regardless of cause — network timeout, Apple credential expiry, server error, user cancellation (already silently suppressed).
- Why it matters: Returning users on safety-mission app may access in charged moment. Opaque error with no hint breaks calm-companion contract and creates dead-end. If Apple session expired, "try again" will keep failing.
- Fix: Map common error codes to distinct copy variants. Minimum viable: "No connection — check your network and try again" vs. "Sign-in failed. Please try again in a moment." Add soft support touch ("Still stuck? [Get help]") for persistent failure.

**[P1] "or" divider creates false parallel**
- What: Divider with "or" label sits between primary CTA and "Don't have an account? Sign up" link. "Or" implies peer alternatives — second auth method or peer action. "Sign up" is not peer auth method; it's routing escape.
- Why it matters: Users scan dividers as "here are my options." Implied question "what are my choices?" answered incorrectly — users may wonder if email auth or Google missing.
- Fix: Remove divider entirely or replace "or" with visual separator only. Treat "Don't have an account?" as footer copy below CTA, not peer choice.

**[P1] No post-sign-in destination communication**
- What: User has no idea where they'll land after tapping "Log in with Apple." App routes to `/home` — correct behavior — but nothing on screen implies this.
- Why it matters: For safety app, user's mental model of "what happens next" matters. If not sure they'll land on right screen, may hesitate at the door.
- Fix: Add subtitle under "Welcome back" — "Pick up where you left off." — in `subheadlineRegular`. 1-2 words that close the loop.

**[P2] `loginLink` inherits `loginPrompt` size but cross-references `footnoteEmphasized` weight**
- What: `loginLink` does `fontWeight: typography.footnoteEmphasized.fontWeight` — borrowing weight from 13pt token while rendered size is 15pt.
- Why it matters: Not visual bug today but fragile — if `footnoteEmphasized.fontWeight` ever changes, silently affects 15pt "Sign up" link. Fails `.cursorrules` anti-slop rule #2.
- Fix: Define weight directly as `fontWeight: '600'` or add `subheadlineEmphasized.fontWeight` reference. Apply to `get-started.tsx` simultaneously (clone has identical drift).

**[P2] Missing `spacing` and `radii` token adoption**
- What: `paddingHorizontal: 32`, `height: 48`, `borderRadius: 100`, `paddingVertical: 16`, `gap: 88`, `gap: 16`, `gap: 8` all hardcoded numeric values. `spacing` and `radii` tokens unused.
- Why it matters: `.cursorrules` anti-slop rule #2 explicit: "Never write a hex color, font size, or spacing value inline."
- Fix: Import `spacing` and `radii`; replace inline values. 88pt gap warrants named export or comment. Apply to `get-started.tsx` simultaneously.

**[P3] `dividerLine` uses `colors.wiltedgreen` rather than `dividerOnDark` token**
- What: `dividerLine` is `backgroundColor: colors.wiltedgreen` on `colors.burntgreen` ground. Semantic `dividerOnDark` token exists (`rgba(160, 214, 164, 0.25)`) — specifically created for "hairline dividers on wiltedgreen."
- Why it matters: Divider using brand-color token in decorative/separator role. Semantic separator token exists for this case.
- Fix: Replace with `backgroundColor: colors.dividerOnDark`. Same fix applies to `get-started.tsx`.

## Persona Red Flags

**Sam (accessibility):**
Screen performs well for Sam — tap targets compliant, VoiceOver labels explicit and correct, `accessibilityState.busy` tells AT button is loading. One gap: `ActivityIndicator` has no `accessibilityLabel` of its own — VoiceOver reads button's role/state but spinner itself may be announced as unlabeled. Error text has no `accessibilityLiveRegion` — Sam may not be informed error appeared. Add `accessibilityLiveRegion="polite"` to error `<Text>`.

**Casey (distracted mobile):**
CTA at 48pt reachable, vertically centered, lands in middle-to-lower half. Error state small (13pt) may be missed at glance. "Please try again" gives Casey no actionable next step. No haptic on failure (`Haptics.NotificationFeedbackType.Error` would be right cue), no visual prominence change to error copy.

**Black driver assessing safety in a charged moment:**
Persona where screen's gap matters most. Driver trying to access app before or during difficult stop hitting opaque "Sign-in failed" with no recovery path creates friction at worst possible time. Calm-companion brand must extend into error states. Absence of error haptic means no tactile confirmation tap registered but failed. Missing `accessibilityLiveRegion` compounds this. Screen needs: (1) error haptic, (2) error live region, (3) differentiated error copy, (4) "not working? contact us" escape.

## Minor Observations

- `borderColor: colors.wiltedgreen` on outlined button is visual contrast mechanism against `burntgreen` ground — thoughtful and correct. However, wiltedgreen border on burntgreen background is relatively low-contrast. Worth checking against WCAG 3:1 for UI component boundaries.
- `StatusBar style="light"` set on screen root, not inside `Stack.Screen` options block — if router transitions back without replacing status bar, brief flash. Known expo-router papercut.
- `get-started-cars.png` filename anchored to `get-started`, not generic `auth-cars` — future-refactor note if cars illustration diverges.
- Comment on `loginLink` references "2026-06-01 text-size audit" — useful provenance tracking.

## Questions to Consider

2. Should `Haptics.NotificationFeedbackType.Error` be added to catch block for both screens symmetrically?
3. Is "or" divider load-bearing (second auth path planned for v2), or purely aesthetic? If no second auth planned, removing simplifies and eliminates false-parallel implication.
4. Is `/home` destination after login always correct, or could user arrive after deep-link redirect param?
