## Emotional Journey

**Picker state:** Opens with low-friction, visually legible 2×3 grid of illustrated tiles. Steady companion brand register present — orange identity glyph and "Flag what's going on near you" copy is inviting, not alarming. Scrim over live map keeps spatial context visible.

**Detail state:** Emotional temperature rises slightly. For sensitive categories, anonymous-note disclosure is reassuring. But form asks user to make 3 independent choices after already making category choice. For user reporting something they just experienced, too many decisions. Subtitle "Reports like yours keep Fresh Greens fresh." reads as community warmth in calm context but feels tonally off when someone is reporting feeling unsafe.

**Thank-You state:** Confirmation clean, doesn't over-promise. "Thanks for sharing." appropriately low-key. Undo affordance (CaretLeft) is a good safety valve but icon-as-undo is cognitive friction. Repeated subtitle from detail lands as lazy copy-paste in this otherwise warm moment.

**Net arc:** Picker (calm, inviting) → Detail (neutral-to-taxing) → Thank-You (muted warmth). Works for casual positive reports. For sensitive reports (felt-unsafe, incident), form feels cold and thank-you generic. Emotional gap biggest exactly when user is most vulnerable.

## What's Working

**1. Reserved-color discipline is clean.** Orange only via documented exception SVG; UI chrome entirely freshgreen/wiltedgreen/neutral. Separation intact — future orange warning chip still carries signal weight.

**2. Tap-target compliance throughout.** All interactive elements use `tapTarget44` or `minHeight: 44` with painted targets. `hitSlop: 8` exception on photo-clear badge well-reasoned (comment explains why 12 would steal retake taps).

**3. State machine clarity.** Picker → detail → thank-you arc handled entirely in local state with clean transitions. `accessibilityViewIsModal` wired. `KeyboardAvoidingView` + `ScrollView` combination handles tall felt-welcome form. GPS fallback chain well-defended.

## Priority Issues

**[P1] Thank-You "back" icon invokes undo — mental model mismatch**
- What: `ThankYouView` renders `CaretLeft` with `accessibilityLabel="Undo submission and go back"` wired to `handleUndo`, which calls `removeCommunityReport`. Chevron-left glyph universally means "navigate back" in iOS; here means "delete my submission."
- Why it matters: User tapping "back" expecting to return to detail view to edit will instead delete report silently. For Black driver reporting felt-unsafe who changes their mind, destroys contribution. Worst for anxious users relying on muscle memory.
- Fix: Replace `CaretLeft` with explicit undo affordance — labeled text button ("Undo") in header row's leading position, or secondary outlined `Button` below Close CTA. Reserve chevron for genuine back-navigation only.

**[P1] Disabled Submit button explains nothing**
- What: When `locationKnown` is false, Submit Button renders `disabled={true}` with no other signal. No spinner, no explanatory copy, no `accessibilityHint`.
- Why it matters: GPS acquisition can take 2-10 seconds. User who taps Submit and sees nothing will tap again, assume app broken, or abandon. For Casey (distracted driver), silent dead end. For VoiceOver users, button "unavailable" with no path forward.
- Fix: (a) Add `accessibilityHint="Waiting for your location"` when `!locationKnown`. (b) Add inline status line below form ("Getting your location…") while GPS pending. (c) Show CTA as loading rather than disabled.

**[P2] Discarding filled detail form has no guard**
- What: X (close) and CaretLeft (back from detail) both call handlers that reset all form state — `detailText`, `selectedSubTag`, `photoUri` — without confirm step.
- Why it matters: User who typed description, attached photo, reconsiders category loses all work with single tap. Back resets to picker; X closes modal entirely.
- Fix: If `detailText.length > 0 || photoUri || selectedSubTag`, intercept Back and Close with `Alert.alert` confirm: "Discard this report?" / [Cancel, Discard]. Three lines. Well-established iOS convention.

**[P2] Sensitive-category subtitle ignores emotional register**
- What: All categories share subtitle "Reports like yours keep Fresh Greens fresh." Works for positive-contribution categories but mismatched to felt-unsafe and incident, where user is reporting something that happened to them.
- Why it matters: Brand is "Steady Companion" — calm, grounded, acknowledging. Telling user reporting they felt unsafe that their report "keeps Fresh Greens fresh" is breezy community-marketing in wrong moment.
- Fix: Per-category subtitle copy for sensitive categories. For `felt-unsafe`: "Your experience matters. Tell us what happened." For `incident`: "Reporting helps others on the same roads." Keep existing for positive categories. `category.subtitle` field already exists on `ReportCategory` type.

**[P2] Character counter missing for 280-char text input**
- What: `TextInput` has `maxLength={280}` but no remaining-character counter visible. Cap silently prevents further typing once hit.
- Why it matters: User writing detailed account of incident will hit wall without warning. 280 is meaningful reference but affordance needs to be visible.
- Fix: Render `{280 - detailText.length}` counter as `caption1Regular` in `labelTertiary` right-aligned below TextInput, conditionally visible when `detailText.length > 0`. Shift to `colors.red` when `< 20` chars remain (form-validation signal, documented exception #8).

**[P3] Identical subtitle in detail and thank-you breaks copy voice**
- What: String "Reports like yours keep Fresh Greens fresh." hardcoded as `styles.subtitle` in detail view and as constant `subtitle` in `ThankYouView`.
- Why it matters: Reads as template artifact, not voice. Thank-you moment is the one place app has user's attention and goodwill — wasting on recycled copy undersells contribution.
- Fix: Give Thank-You its own closing line aligned with Steady Companion register: "Your note is on the map." or "The community sees it."

## Persona Red Flags

**Sam (accessibility):**
Three live issues. (1) Disabled Submit no `accessibilityHint` — VoiceOver announces "Submit report, button, dimmed" with no path to resolve blocker. (2) Sub-tag chip groups use `accessibilityRole="header"` correctly, but single-select semantics communicated only by `accessibilityState={{ selected: active }}` — no `accessibilityRole="radio"` group wrapper. (3) The `&rsquo;` HTML entity in picker subtitle will render literally as the character string.

**Casey (distracted mobile):**
Silent disabled Submit primary risk. Casey taps Submit, nothing happens, taps again, in a car ends in abandonment. Picker grid tiles generously sized for one-handed tapping. Scrollable detail form requires vertical attention — for category with 3 chip groups, Casey may not scroll far enough to see CTA exists.

**Black driver assessing safety in a charged moment:**
Highest-stakes use case. Three friction points: (1) felt-unsafe and incident render generic "Reports like yours keep Fresh Greens fresh." subtitle — copy asks user to frame charged personal experience as community contribution, requiring composure moment doesn't afford. (2) Anonymous-note disclosure appears in `footnoteRegular` / `labelTertiary` below subtitle — low-contrast, small-text, below fold of title block — should be visually elevated. (3) If GPS not available, Submit disabled with no explanation. For user trying to document racially charged traffic stop, being silently blocked is a dignity failure.

## Minor Observations

- `identityIcon` and `detailIdentityIcon` have identical property values. Consolidate.
- `paddingHorizontal: 14` on `.chip` not a spacing-scale step. Use `spacing.md` (16) or add `12` as a scale step.
- Scrim `Pressable` has `accessibilityRole="button"` and `accessibilityLabel="Dismiss report"` correct but no `accessibilityHint`.
- `&rsquo;` in picker subtitle JSX. RN's `<Text>` does not process HTML entities — renders as literal `&rsquo;` on screen. Use `{'’'}` or plain apostrophe.
- `ThankYouView` receives `placeName` prop but immediately ignores it.
- Photo stub and preview container same height. Preview `borderRadius: 16` not token-sourced — should be `radii.lg`.

## Questions to Consider

1. What is the intended UX when `locationKnown` remains false indefinitely? Currently Submit stays disabled forever. Should there be timeout after which user is offered "Submit without precise location" path?
2. Felt-unsafe vs. incident disambiguation — what is the meaningful user-facing difference? Should they be collapsed into one "Something felt wrong" category with sub-tag for type?
3. Undo window — `handleUndo` calls `removeCommunityReport` immediately. Race condition where report has already been sent to other users' map views before undo fires?
4. Sub-tag single-select for felt-welcome — user might want to select both "Restaurant" and "Black-owned" in single felt-welcome report. Deliberate scope constraint?
5. Thank-you "what happens next" — gives no signal about when contribution will appear on map. Even single sentence ("Your pin is now on the map.") closes loop.
