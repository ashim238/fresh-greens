## Anti-Patterns Verdict

Not AI slop. The state-machine comment block at the top is the kind of engineering documentation a human writes after living with edge cases. Design choices are coherent with rationale (silent autocomplete miss, `lastQueryRef` stale-guard, the `relativeWhen` formatter, `recentsLoading` flash guard) — they solve real problems. Token discipline is 95% clean. No gradient text, no glassmorphism, no eyebrow-labeled card grids.

One soft flag: Quick Tool tiles at 144×~96pt with a centered icon-then-label stack feel slightly over-engineered for a one-tap category filter — they echo "polished card grid" anti-pattern. Verdict: **human-made**.

## Emotional Journey

**Peak — Upcoming event row:** Driver sees upcoming event with resolved address and "in 3h" badge, taps it, immediately routed. Highest-trust moment: the app did work on the user's behalf without being asked. Single tap to navigate.

**Valley — unresolved event row:** "Set location · in 3h" is accurate but lands flat. User has no mental model for what "Set location" means here (a pick sheet will appear), and the row is visually identical to a resolved event except for the subtext.

**Reassurance in charged moments:** Error states handle the charged moment well — icon-swap between MagnifyingGlass and WifiSlash prevents misattribution. Loading copy "Charting course…" is calm and on-brand. Gap: if user taps Quick Tool category while location is unavailable, error copy is same as network failure with no orienting frame.

## What's Working

**1. Silent debounce pattern on autocomplete.** The 300ms setTimeout + silent failure on miss mirrors Apple Maps precisely. `lastQueryRef` guard preventing stale-result overwrite is production-quality detail.

**2. The `recentClearBtn` minimum-height pattern.** The "Clear" text link is styled at `minHeight: 44` + `justifyContent: 'center'` — genuine 44pt painted tap target on what could easily have been an undersized affordance.

**3. The `buildSavedRows` merge with ~200m dedup.** Function that merges saved places and regular destinations, skipping regulars within `SAVED_MATCH_DELTA` of a saved place. Cross-module coherence that builds trust in data quality.

## Priority Issues

**[P1] Mic icon announces as a button VoiceOver cannot activate**
- What: `PressableIcon` in SearchBar wraps mic icon. `onMicPress` undefined in search.tsx. `PressableIcon` checks `if (!onPress)` and renders non-pressable `View` — so VoiceOver actually handled correctly. But `accessibilityLabel="Voice search"` is still passed, and the icon is visible to sighted users with no affordance that it's inert. Sighted user tapping gets no feedback.
- Why it matters: Steady Companion register requires every visible affordance produces a response. Icon that looks tappable but isn't creates micro-friction and mild trust erosion.
- Fix: Hide the mic icon entirely in `on-tap`/`typing` states (cleanest), or render with `opacity: 0.35` and `accessibilityElementsHidden={true}`. Remove `accessibilityLabel` from inert path.

**[P2] Error state for missing location has no recovery action**
- What: When `userLocation` is null and user submits, error state shows "Locating you… try again in a moment." No retry button, no cancel, no explanation.
- Why it matters: Most likely on first launch or after permission reset. User may conclude app is broken.
- Fix: Add `retry` action prop to `ErrorState` (or inline retry Pressable) that re-triggers `Location.getCurrentPositionAsync`. Copy: "Still finding your location — tap to try again."

**[P2] Token discipline slips in Quick Tool tile and scroll container styles**
- What: Three raw values escape theme system: `quickTool.borderRadius: 8` should be `radii.sm`; `quickToolsRow.gap: 16` and `scrollContent.gap: 16` should be `spacing.md`.
- Why it matters: Cursorrules anti-slop check 2: "Never write a hex color, font size, or spacing value inline in a screen." Three slips can seed a pattern.
- Fix: Replace with `radii.sm` and `spacing.md` from theme imports.

**[P2] Unresolved Upcoming row gives no pre-tap affordance for what "Set location" means**
- What: Row reads `Set location · in 3h` in `recentSubtext` — visually identical to resolved row's subtitle. No icon, color cue, or typography distinction.
- Why it matters: Driver expects navigation, gets pick sheet. Unexpected UI interruption at planning moment.
- Fix: Add trailing `CaretRight` (`labelTertiary`, 16pt) to signal "tap to configure", or change subtext color to `freshgreen` for actionable read.

**[P3] Demo-price footnote is visually orphaned**
- What: `"Sample fuel prices for demo — not live pump data."` renders in `footnoteRegular` at `labelTertiary` with no container; same color/size as result address text, easily read as stale address.
- Why it matters: Honesty-of-disclosure principle requires the footnote to read as a footnote, not content.
- Fix: Indent to match result rows (`paddingHorizontal: 48`), or wrap in translucent `fillsQuaternary` chip with `*` prefix.

**[P3] "Clear" in Recent header has asymmetric tap-target**
- What: `recentClearBtn` has `minHeight: 44` (compliant) but no `paddingHorizontal` — painted width equals text width of "Clear" (~32pt). Horizontal target sub-44pt, violating cursorrules.
- Why it matters: "Clear" is destructive. Narrow tap target on destructive control is a miss in both directions.
- Fix: Add `paddingHorizontal: spacing.md` widens painted target to ~64pt.

## Persona Red Flags

**Sam (accessibility):**
- Mic icon's static-but-visible state in `on-tap` is a VoiceOver dead zone.
- Long-press-to-remove on recents may conflict with VoiceOver's default long-press gesture (rotor action). Needs device testing.
- Quick Tool tile `accessibilityState={{ selected: isSelected }}` is correct.

**Casey (distracted mobile):**
- Quick Tool tile at 144×~96pt easily one-handed tapped.
- Back chevron compliant 44×44 but sits at far left edge — reachable with left thumb but awkward stretch on Max.
- "Clear" button's sub-44pt horizontal target sharpest risk for Casey.

**Black driver assessing safety in a charged moment:**
- "Locating you… try again in a moment" with no retry is worst possible response in time-sensitive planning moment. They cannot proceed; no action.
- Unresolved Upcoming row breaks flow — tap that should start routing opens pick sheet instead.

## Minor Observations

- `resultsCity` initializes to `'your area'` — if reverse-geocode never resolves, subhead reads "in your area" lowercase-inconsistent with city names.
- Fuel section has no explicit `alignItems` on the row; default `stretch` could behave unexpectedly at Dynamic Type XXL.
- `PressableIcon` passes `size = name === 'mic' ? 20 : 24` — mic renders 4pt smaller than other icons. Intentional but undocumented.
- `clearRecents` Alert says "Forget all your recent destinations?" — voice of the app, lands gently — but "This cannot be undone." pivots to clinical register.
- `scrollContent` gap creates consistent vertical rhythm but Upcoming/Saved sit inside `recentSection` (`paddingHorizontal: 24`) while Quick Tools sit inside `quickToolsRow` (`paddingHorizontal: 16`). 8pt inconsistency in left-edge alignment.

## Questions to Consider

- Should the silent debounce add a very lightweight in-progress signal (a `fillsQuaternary` animated dot, not a full LoadingState) to the `typing` phase?
- Quick Tool tiles at 144×~96pt are generous — more a card than a filter chip. iOS Maps uses a compact horizontal chip row. Worth a Figma comparison at actual phone size.
- Should Upcoming surface above Quick Tools on landing state when events are imminent (< 2h)?
- Is there a ticket for the mic icon's voice-input unlock, or is it at risk of staying decorative ghost indefinitely?
- Saved section accessibility: revealed inline — consider `accessibilityLiveRegion="polite"` on the container so VoiceOver announces newly-revealed content.
